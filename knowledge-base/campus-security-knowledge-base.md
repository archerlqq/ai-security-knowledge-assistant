# 高校网络安全知识库

本知识库用于支持高校师生或企业员工在账号安全、钓鱼邮件、数据安全、权限申请和 AI 安全边界等场景中的安全咨询问答。系统只提供防御性、合规性和流程性建议，不提供攻击、绕过、破解、入侵等危险操作方法。

---

# 一、账号安全 FAQ

## 1. 账号疑似被盗怎么办

如果用户发现账号疑似被盗，应立即停止继续使用该账号进行重要操作，并尽快修改密码。修改密码时，应避免使用与旧密码相似的组合，也不要使用生日、手机号、姓名拼音、简单数字等容易被猜到的信息。

用户还应检查近期登录记录、账号绑定信息、邮箱、手机号和多因素认证设置。如果发现异常登录、陌生设备、异常绑定或权限变化，应及时联系信息中心或系统管理员处理。

如果该账号涉及重要系统、管理权限、数据访问权限或财务相关操作，应将风险等级视为较高，建议立即联系管理员进行冻结、核查或权限回收。

## 2. 如何设置强密码

强密码应具备足够长度和复杂度，建议同时包含大小写字母、数字和符号，并避免使用个人信息、常见词语、连续数字或重复字符。

不同系统应尽量使用不同密码，避免多个平台共用同一密码。如果一个平台发生密码泄露，共用密码可能导致其他账号也受到影响。

## 3. 什么是多因素认证

多因素认证是指除密码之外，再增加短信验证码、动态口令、认证 App、硬件密钥等额外验证方式。它可以降低单一密码泄露带来的风险。

对于重要系统、管理后台、邮箱和云服务账号，建议开启多因素认证。

## 4. 收到异常登录提醒怎么办

如果用户收到异常登录提醒，应先确认是否为本人操作。如果不是本人操作，应立即修改密码，并检查账号绑定信息、登录设备和近期操作记录。

如账号涉及重要系统或敏感数据访问，应联系管理员进行安全核查。

## 5. 账号安全处理原则

账号安全问题应遵循以下原则：

1. 及时修改密码。
2. 检查异常登录和绑定信息。
3. 避免继续使用疑似异常账号处理重要事务。
4. 涉及重要系统或敏感数据时联系管理员。
5. 不向任何人提供密码、验证码或账号凭证。

# 二、钓鱼邮件识别和处理指南

## 1. 什么是钓鱼邮件

钓鱼邮件是指伪装成学校、企业、平台、银行、快递、通知系统等可信来源，诱导用户点击链接、下载附件、填写账号密码或提供验证码的邮件。

钓鱼邮件的风险在于，它可能导致账号被盗、敏感信息泄露、恶意软件感染或权限被滥用。

## 2. 如何识别可疑邮件

用户可以从以下方面判断邮件是否可疑：

1. 发件人地址是否异常，例如域名拼写错误、使用陌生邮箱或与官方域名不一致。
2. 邮件是否制造紧张感，例如要求立即处理、否则封号、停用账号或影响权限。
3. 邮件中是否包含陌生链接、短链接、附件或二维码。
4. 邮件是否要求输入账号、密码、验证码、身份证号等敏感信息。
5. 邮件措辞是否存在明显错误、格式异常或内容不符合正常流程。

## 3. 收到疑似钓鱼邮件怎么办

用户收到疑似钓鱼邮件时，不应点击邮件中的链接，不应下载附件，也不应扫描二维码或填写个人信息。

建议用户先通过官方渠道核实邮件真实性。如果无法判断，应将邮件转发或截图给信息中心、安全管理员或相关负责人进行核验。

如果用户已经点击链接或提交了账号密码，应立即修改密码，并联系管理员检查账号状态。

## 4. 为什么不能随意点击邮件链接

钓鱼邮件中的链接可能指向伪造登录页或恶意网站。用户输入账号密码后，攻击者可能获取账号凭证并进一步访问系统或数据。

因此，涉及登录、支付、权限、账号验证等操作时，应优先通过官方网站或系统入口访问，而不是直接点击邮件中的链接。

## 5. 钓鱼邮件处理原则

1. 不点击可疑链接。
2. 不下载未知附件。
3. 不填写账号密码和验证码。
4. 通过官方渠道核实。
5. 已经点击或提交信息时，及时修改密码并联系管理员。

# 三、数据安全与个人信息处理指南

## 1. 什么是敏感数据

敏感数据包括但不限于个人身份信息、学生信息、联系方式、身份证号、账号凭证、成绩信息、科研数据、业务数据、系统日志、访问权限信息等。

在高校或企业场景中，学生名单、联系方式、成绩表、科研资料、内部系统数据等都可能涉及数据安全风险。

## 2. 处理个人信息时应注意什么

处理个人信息时，应遵循必要、最小、明确用途的原则。只收集完成业务所必需的信息，不应随意扩大收集范围。

在共享、传输、存储个人信息时，应确认接收对象、使用目的和保存方式是否合理。对于包含大量个人信息的文件，应避免通过公开网盘、社交群聊或不受控平台传输。

## 3. 学生名单能不能发到微信群

如果学生名单包含姓名、学号、手机号、身份证号、成绩、家庭住址等信息，应谨慎处理。是否可以发送，需要看发送目的、群成员范围、是否有必要、是否经过授权以及是否存在泄露风险。

一般情况下，不建议将包含个人信息的表格直接发送到非正式群聊中。更稳妥的做法是使用学校或企业指定系统，或在必要时进行脱敏处理。

## 4. 科研数据能不能上传个人网盘

科研数据是否可以上传个人网盘，需要考虑数据性质、课题要求、合作协议、保密要求和平台安全性。

对于涉及未公开成果、合作单位资料、个人信息、敏感实验数据或商业秘密的数据，不建议上传到个人网盘或不受控平台。应优先使用学校或机构指定的存储系统。

## 5. 数据安全处理原则

1. 只收集必要数据。
2. 避免通过不受控渠道传输敏感数据。
3. 涉及个人信息时注意脱敏和访问范围。
4. 重要数据应使用指定系统存储。
5. 发生误发、泄露或异常访问时，应及时联系管理员。

# 四、权限申请与访问控制指南

## 1. 什么是最小权限原则

最小权限原则是指用户只应拥有完成当前工作所必需的最低权限，不应长期持有与工作无关或超出职责范围的权限。

最小权限可以降低账号被盗、误操作、越权访问和数据泄露的风险。

## 2. 如何申请系统权限

申请系统权限时，用户应说明申请原因、使用场景、所需权限范围、使用期限和审批人。权限申请应通过学校或企业指定流程提交，不建议通过口头、私聊或非正式方式授予权限。

管理员在审批时，应确认申请是否必要、权限范围是否合理、是否存在替代方案，以及权限是否需要设置有效期。

## 3. 临时权限如何处理

临时权限应设置明确有效期。使用结束后，应及时回收权限，避免权限长期保留。

如果临时权限涉及敏感系统、管理后台或重要数据访问，应加强审批和记录。

## 4. 外部人员访问系统需要注意什么

外部人员访问系统应经过正式审批，明确访问目的、访问范围、访问期限和责任人。不应随意共享内部账号或将个人账号借给外部人员使用。

外部访问结束后，应及时关闭账号或回收权限。

## 5. 权限异常怎么办

如果用户发现自己拥有不应拥有的权限，或发现他人疑似越权访问，应及时联系系统管理员核查。

如果权限异常涉及敏感数据、管理后台或重要系统，应视为较高风险问题处理。

## 6. 权限管理原则

1. 权限申请应有明确目的。
2. 权限范围应尽量小。
3. 临时权限应设置有效期。
4. 外部访问应正式审批。
5. 权限异常应及时联系管理员。

# 五、AI 安全边界与拒答策略

## 1. 系统定位

本系统是面向高校师生或企业员工的网络安全知识库 AI 助手，主要用于安全制度问答、账号安全咨询、钓鱼邮件处理、数据安全说明、权限申请流程查询和风险提示。

系统的目标是提供防御性、合规性、流程性建议，不提供攻击、绕过、破解、入侵、恶意利用等操作方法。

## 2. 可以回答的问题

系统可以回答以下类型的问题：

1. 如何识别钓鱼邮件。
2. 账号疑似被盗后如何处理。
3. 如何设置强密码。
4. 如何申请系统权限。
5. 个人信息处理时需要注意什么。
6. 数据误发后应该联系谁。
7. 如何判断问题是否需要联系管理员。
8. 网络安全制度和流程相关问题。

## 3. 应该拒答的问题

如果用户提出以下类型请求，系统应拒绝提供具体方法：

1. 攻击、入侵、破解、绕过认证相关请求。
2. 获取他人账号、密码、验证码或隐私信息的请求。
3. 绕过系统权限、登录限制或安全策略的请求。
4. 恶意利用漏洞、破坏系统、窃取数据的请求。
5. 任何可能造成未授权访问、数据泄露或系统损害的请求。

## 4. 拒答时应该如何回答

当用户提出高风险或不合规请求时，系统应使用安全、简洁的方式拒答，并提供合规替代路径。

建议回复格式：

该问题涉及潜在违规或高风险操作，系统无法提供具体方法。
如果这是正式安全测试、合规检查或课程实验需求，请通过学校或企业的授权流程申请。
如果你发现系统异常、安全漏洞或账号风险，请及时联系信息中心或安全管理员。

## 5. 不应收集的信息

系统不应要求用户提交以下信息：

1. 密码。
2. 验证码。
3. 身份证号。
4. 银行卡信息。
5. 账号凭证。
6. 真实敏感业务数据。
7. 未脱敏的个人信息文件。

## 6. 安全边界原则

1. 只提供防御性和合规性建议。
2. 不提供危险操作步骤。
3. 不鼓励绕过授权流程。
4. 遇到高风险问题时建议联系管理员。
5. 知识库没有依据时，不编造答案。
