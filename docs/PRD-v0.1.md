## 2. 项目背景

在高校或企业内部，普通用户经常会遇到账号异常、钓鱼邮件、权限申请、数据安全和个人信息处理等网络安全相关问题。但相关制度和流程通常分散在多个文档或通知中，普通用户查询和理解成本较高。与此同时，信息中心或安全管理员需要重复回答大量基础安全咨询，人工沟通成本较高。

因此，本项目希望通过 RAG 知识库和大模型问答能力，将分散的网络安全 FAQ、制度说明和处理流程转化为可交互的 AI 助手，帮助用户快速获得安全问答、风险等级提示、处理建议和高风险问题拒答提示。

## 3. 产品目标

1. 帮助普通用户快速获得网络安全问题的解释、风险判断和处理建议。
2. 减少重复性安全咨询，沉淀高频问题和 Bad Case。
3. 验证 RAG 知识库、Prompt 约束、风险等级判断和拒答策略在安全咨询场景中的可行性。

## 4. 目标用户

### 4.1 普通学生 / 普通员工

这类用户主要在日常使用邮箱、账号、系统和文件传输工具时遇到安全问题，需要快速获得清晰、可执行的处理建议。

### 4.2 老师 / 部门管理员

这类用户更常涉及数据安全、权限申请、学生信息处理和外部协作等场景，需要获得制度依据和流程说明。

### 4.3 信息中心 / 安全管理员

这类用户关注重复咨询减少、高频问题归类、Bad Case 沉淀和知识库持续优化。

| 场景编号 | 场景名称 | 用户问题 | 产品响应 |
| --- | --- | --- | --- |
| S001 | 钓鱼邮件处理 | 收到可疑邮件，不知道能不能点击 | 提供识别方法、风险等级和处理建议 |
| S002 | 账号异常处理 | 账号疑似被盗或异地登录 | 提示修改密码、检查记录、联系管理员 |

| S005 | 高风险问题边界 | 用户提出危险或违规请求 | 拒答并提示正式授权或转人工 |

## 6. 需求范围

### 6.1 MVP 范围

1. 安全知识问答
2. 问题类型识别
3. 风险等级提示
4. 处理建议生成
5. 高风险问题拒答
6. 用户反馈与 Bad Case 记录

### 6.2 非目标范围

1. 不做真实工单系统。
2. 不做复杂权限管理。
3. 不接入真实敏感数据。
4. 不提供攻击、绕过、入侵、破解等危险操作方法。
5. 不做企业级部署。

## 8. 用户流程

用户打开 AI 助手 → 输入网络安全问题 → 系统识别问题类型 → 系统判断是否属于高风险请求 → 如果是高风险请求，系统拒答并提示联系管理员 → 如果是普通问题，系统检索知识库 → 系统生成结构化回答 → 展示问题类型、风险等级、回答内容、处理建议和引用来源 → 用户反馈“有帮助 / 没帮助” → 系统记录反馈和 Bad Case。

## 9. 功能详细说明

### F001 安全知识问答

功能描述：  
用户输入网络安全相关问题后，系统基于知识库内容生成回答，帮助用户获得安全解释和处理建议。

使用角色：  
普通学生、普通员工、老师、部门管理员。

前置条件：  
系统已配置网络安全知识库，知识库中包含账号安全、钓鱼邮件、数据安全、权限申请等基础文档。

输入内容：  
用户输入的自然语言问题。

处理逻辑：  
系统接收用户问题后，先检索知识库中相关内容，再将检索结果作为上下文传递给大模型，生成结构化回答。

输出结果：  
系统输出问题类型、风险等级、回答内容、处理建议和引用来源。

异常情况：  
如果知识库中没有足够依据，系统应提示“当前知识库无法确认”，并建议用户联系管理员，而不是编造答案。

验收标准：  
输入常见安全问题时，系统能够给出结构清晰、内容基本准确、包含处理建议的回答。

### F002 问题类型识别

功能描述：  
系统根据用户输入内容判断问题类型，便于后续风险判断、知识库检索和统计分析。

问题类型包括：  
账号安全、钓鱼邮件、数据安全、权限管理、终端安全、高风险请求、其他。

输出结果：  
系统在回答中展示问题类型。

验收标准：  
测试集中常见问题能够被归入合理类别。

### F003 风险等级提示

功能描述：  
系统根据用户问题内容输出低风险、中风险或高风险等级，帮助用户判断问题严重程度。

风险等级说明：  
低风险：普通安全知识咨询。  
中风险：可能涉及账号、权限、数据操作风险，需要谨慎处理。  
高风险：可能涉及账号泄露、数据泄露、高危操作或需要管理员介入的问题。

验收标准：  
模型输出的风险等级与测试集中 expected_risk_level 基本一致。

### F004 处理建议

功能描述：  
系统根据问题类型和风险等级，给出下一步处理建议。

输出结果：  
处理建议应尽量清晰、可执行，例如不要点击链接、修改密码、检查登录记录、联系信息中心、走权限申请流程等。

验收标准：  
回答中应包含至少一条明确的下一步操作建议。

### F005 高风险问题拒答

功能描述：  
当用户问题涉及攻击、绕过、入侵、破解、恶意利用等高风险内容时，系统不提供具体方法，而是进行拒答并提示正式授权或转人工。

输出结果：  
系统提示该问题涉及高风险或违规操作，无法提供具体方法，并建议通过正式授权流程或联系信息中心、安全管理员。

验收标准：  
测试集中标记为 should_refuse = 是的问题，系统应拒绝输出具体危险方法。

### F006 用户反馈与 Bad Case 记录

功能描述：  
用户可对回答进行“有帮助 / 没帮助”反馈。对于无帮助回答，系统记录问题、回答、错误类型和迭代建议，用于后续优化。

验收标准：  
系统能够沉淀测试问题、模型回答、是否正确、错误类型和迭代建议。

## 10. 页面原型说明

| 页面编号 | 页面名称 | 页面说明 |
| --- | --- | --- |
| P001 | 首页 / 提问入口 | 展示产品介绍、输入框和快捷问题 |
| P002 | 问答结果页 | 展示 AI 回答、风险等级、处理建议和引用来源 |
| P003 | 高风险拒答页 | 展示拒答提示和转人工建议 |
| P004 | 用户反馈页 | 用户标记回答是否有帮助，可补充反馈原因 |
| P005 | Bad Case 分析页 | 展示错误类型、问题列表和迭代建议 |

## 11. 数据指标

| 指标 | 含义 | 计算方式 / 判断方式 |
| --- | --- | --- |
| 回答准确率 | 回答是否覆盖期望要点 | 正确回答数 / 测试问题总数 |
| 风险等级准确率 | 模型风险等级是否符合预期 | 风险等级正确数 / 测试问题总数 |
| 拒答准确率 | 高风险请求是否正确拒答 | 正确拒答数 / 应拒答问题数 |
| Bad Case 占比 | 错误案例占比 | Bad Case 数 / 测试问题总数 |
| 有帮助率 | 用户反馈有帮助比例 | 有帮助反馈数 / 总反馈数 |

## 12. 权限与角色

MVP 阶段暂不做复杂权限系统，仅区分普通用户和管理员视角。

普通用户：  
可以提问、查看回答、提交反馈。

管理员：  
可以查看 Bad Case 记录、错误类型统计和知识库优化建议。

## 13. 异常情况与边界规则

| 异常情况 | 处理方式 |
| --- | --- |
| 知识库无相关内容 | 提示无法确认，建议联系管理员 |
| 用户问题过于模糊 | 引导用户补充具体场景 |
| 用户提出高风险请求 | 拒答，不提供具体方法 |
| 模型回答格式不完整 | 记录 Bad Case，优化 Prompt |
| 风险等级判断错误 | 记录错误类型，补充分类规则 |
| 引用来源错误 | 优化知识库分段和检索配置 |

## 14. 验收标准

1. 用户可以输入安全问题并获得结构化回答。
2. 系统可以输出问题类型、风险等级、处理建议和引用来源。
3. 系统可以对高风险请求进行拒答。
4. 至少完成 50 条测试问题的评测。
5. 测试结果中能够记录模型回答、实际风险等级、是否正确、错误类型和迭代建议。
6. GitHub 中包含 PRD、用户场景文档、AI 产品逻辑文档、测试集和 Bad Case 分析。
7. 项目可以通过 Dify Demo 或 Streamlit Demo 进行演示。

## 15. 后续迭代计划

1. 增加管理员后台，支持高频问题统计和知识库维护。
2. 接入真实工单系统，实现高风险问题转人工流转。
3. 扩展知识库内容，覆盖更多安全制度和合规场景。
4. 优化评测体系，引入更细粒度的回答质量评分。
5. 增加多角色权限，不同用户展示不同范围的知识内容。
