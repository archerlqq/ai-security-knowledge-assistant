# AI 产品逻辑文档：高校网络安全知识库 AI 助手

## 1. 文档目的

本文档用于说明本项目中的 AI 产品逻辑，包括 AI 能力定位、RAG 知识库设计、Prompt 设计、输出结构、风险边界、评测方案和 Bad Case 迭代机制。该文档用于支撑后续 Dify Demo 搭建、产品功能落地和求职作品集展示。

## 2. AI 能力定位

本项目中的 AI 不定位为通用聊天助手，也不定位为专业安全人员的替代品，而是作为网络安全知识检索、问题理解、风险提示和处理建议生成的辅助工具。AI 的主要作用是将分散的安全制度、FAQ 和处理流程转化为用户可理解的自然语言回答，并在回答中提供问题类型、风险等级和后续处理建议。

AI 不负责对真实安全事件做最终判定，也不提供攻击、绕过、入侵、破解等操作性内容。对于高风险或超出知识库范围的问题，系统应拒绝回答具体方法，并建议用户联系信息中心或安全管理员。

## 3. 用户问题与 AI 任务映射

| 用户问题类型 | 用户示例 | AI 任务 | 输出结果 |
| --- | --- | --- | --- |
| 钓鱼邮件 | 收到可疑邮件怎么办？ | 检索知识库并生成解释 | 风险提示 + 处理建议 |
| 账号安全 | 账号疑似被盗怎么办？ | 判断问题类型和风险等级 | 修改密码 + 联系管理员 |
| 数据安全 | 文件能不能发到外部网盘？ | 检索数据安全规范 | 是否可行 + 注意事项 |
| 权限管理 | 如何申请系统权限？ | 检索流程文档 | 申请流程 + 最小权限原则 |
| 终端安全 | 公共 WiFi 有什么风险？ | 检索知识库并并生成解释 | 风险说明 + 注意事项 |
| 其它咨询 | 询问绕过、破解、入侵方法 | 识别风险并拒答 | 拒答 + 正式授权提示 |

## 4. 技术路线选择

本项目选择“Dify + RAG 知识库 + Prompt 约束 + 评测集”的技术路线，而不是直接使用通用大模型对话。原因是网络安全制度、权限流程和数据安全要求具有明确依据，需要保证回答尽量基于知识库内容生成，并能够通过引用来源、测试集和 Bad Case 分析进行持续优化。

| 方案 | 优点 | 问题 | 是否采用 |
| --- | --- | --- | --- |
| 直接问通用大模型 | 搭建简单 | 容易幻觉，缺少依据 | 不作为主方案 |
| RAG 知识库问答 | 可基于文档回答，可追溯 | 依赖知识库质量 | 采用 |
| 微调模型 | 可深度定制 | 成本高，不适合个人项目 | 暂不采用 |
| 规则库系统 | 稳定可控 | 灵活性差，覆盖有限 | 作为补充思路 |

## 5. RAG / 知识库设计

本项目知识库主要由模拟网络安全 FAQ、账号安全说明、钓鱼邮件处理指南、数据安全注意事项、权限申请流程和 AI 安全边界说明组成。知识库不使用真实敏感数据，主要用于验证 RAG 问答在安全咨询场景中的可行性。

知识库初步包括：

1. account-security-faq.md：账号安全 FAQ
2. phishing-email-guide.md：钓鱼邮件处理指南
3. data-security-guide.md：数据安全说明
4. permission-application-guide.md：权限申请流程
5. ai-safety-boundary.md：高风险问题边界

当用户提出问题后，系统先根据问题语义从知识库中检索相关内容，再将检索结果作为上下文输入给大模型，由模型基于上下文生成结构化回答。如果知识库中没有足够依据，系统应提示当前知识库无法确认，而不是编造答案。

## 6. Prompt 设计逻辑

Prompt 的设计目标是让模型在安全咨询场景中保持稳定、可控和可评测。系统 Prompt 将模型角色限定为“网络安全知识库助手”，要求模型优先基于知识库内容回答，并按照固定结构输出问题类型、风险等级、回答内容、处理建议和引用依据。

Prompt 结构包括：

1. 角色设定：你是一个高校/企业内部网络安全知识库助手。
2. 任务说明：根据用户问题和知识库内容，提供安全、清晰、可执行的咨询建议。
3. 回答依据：优先基于知识库内容回答；如果知识库没有依据，不要编造。
4. 输出格式：按照“问题类型、风险等级、简要结论、原因说明、建议操作、是否需要联系管理员”格式输出。
5. 风险边界：不提供攻击、绕过、破解、入侵、恶意利用等具体操作方法。
6. 异常处理：遇到高风险请求时，应拒答并建议联系信息中心或安全管理员。

## 7. 输出结构设计

系统回答采用结构化输出，方便用户理解和后续评测。

标准输出结构如下：

- 问题类型：
- 风险等级：
- 简要结论：
- 原因说明：
- 建议操作：
- 是否需要联系管理员：

结构化输出可以让用户更快理解问题严重程度，也方便后续做评测、反馈记录和 Bad Case 归因。如果每次回答格式都不一致，后续很难统计风险等级、问题类型和回答质量。

## 8. 风险边界与拒答策略

本项目将用户问题分为普通安全咨询、中风险事件和高风险请求三类。

| 类型 | 示例 | 策略 |
| --- | --- | --- |
| 普通安全咨询 | 密码怎么设置更安全？ | 正常回答 |
| 中风险事件 | 账号疑似被盗怎么办？ | 回答处理建议，提示联系管理员 |
| 高风险请求 | 请求绕过、入侵、破解方法 | 拒答，不提供具体方法，建议走授权流程 |

当用户问题涉及攻击、绕过、破解、入侵、恶意利用、窃取账号、规避安全限制等内容时，系统不提供具体操作步骤，不解释可执行方法，而是说明该请求存在风险，并建议用户通过正式授权流程或联系安全管理员处理。

## 9. 效果评测方案

本项目将通过测试集评估 AI 助手的回答质量。测试问题覆盖安全知识问答、账号安全、钓鱼邮件、数据安全、权限申请和高风险拒答边界等类型。

| 指标 | 含义 | 评测方式 |
| --- | --- | --- |
| 回答准确率 | 回答是否符合期望要点 | 人工标注正确/错误 |
| 引用命中率 | 是否引用到相关知识库内容 | 检查引用来源 |
| 风险等级准确率 | 风险等级是否合理 | 对比预期风险等级 |
| 拒答准确率 | 高风险请求是否正确拒答 | 测试拒答类问题 |
| 处理建议有效性 | 建议是否可执行 | 人工判断 |
| Bad Case 占比 | 错误案例占总测试数比例 | 统计测试结果 |

测试集字段包括：

- id <!--问题编号-->
- question <!--用户问题-->
- category <!--问题类型-->
- expected_points <!--期望回答的关键点-->
- expected_risk_level <!--期望风险等级：低 中 高-->
- should_refuse <!--是否应该拒答：是 否-->
- model_answer <!--模型实际回答（测试运行后填写的）-->
- actual_risk_level <!--模型实际判断的风险等级-->
- is_correct <!--人工判断此次模型实际回答是否基本正确-->
- error_type <!--模型回答的不好，要给错误归类-->
- iteration_suggestion

## 10. Bad Case 分类与迭代机制

Bad Case 不是单纯记录模型回答错误，而是用于定位产品、知识库和 Prompt 的改进方向。

Bad Case 初步分类：

1. 回答不准确
2. 回答太泛
3. 引用来源错误
4. 风险等级判断错误
5. 应拒答但未拒答
6. 不该拒答但拒答了
7. 知识库缺失
8. Prompt 规则不清
9. 用户问题表达模糊

当出现 Bad Case 后，首先判断错误来源：如果是知识库缺失，则补充或改写知识库文档；如果是回答格式不稳定，则调整 Prompt 输出结构；如果是风险等级判断错误，则补充风险分类规则；如果是拒答边界不清，则强化高风险请求识别规则。通过“测试集运行—Bad Case 归因—知识库/Prompt 修改—再次测试”的方式形成迭代闭环。

## 11. 后续优化方向

1. 增加更细粒度的问题类型和风险等级规则。
2. 扩展知识库内容，覆盖更多安全制度、FAQ 和处理流程。
3. 增加管理员后台，用于查看高频问题、Bad Case 和知识库缺口。
4. 优化评测集，引入更多边界问题和模糊表达问题。
5. 接入真实工单系统，实现高风险问题转人工流转。
