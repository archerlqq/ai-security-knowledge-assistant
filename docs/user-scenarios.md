# 用户场景文档：高校网络安全知识库 AI 助手

## 1. 文档目的

本文档用于梳理本项目的目标用户、典型使用场景、用户问题、核心痛点和产品机会，为后续 PRD 功能设计、Dify 知识库搭建、Prompt 设计和测试集构建提供依据。

## 2. 目标用户概览

本项目主要面向高校或企业内部的普通用户、部门管理人员和信息安全管理人员。不同用户在网络安全咨询场景中的问题复杂度、风险判断能力和处理目标不同，因此需要分别分析其使用场景和需求。

## 3. 用户角色拆分

### 3.1 普通学生 / 普通员工

这类用户通常没有专业网络安全背景，主要在日常使用邮箱、账号、系统、网络和文件传输工具时遇到安全问题。他们的核心需求不是理解复杂安全原理，而是快速判断问题是否严重、当前应该如何处理，以及是否需要联系管理员。

典型问题：

1. 收到疑似钓鱼邮件怎么办？
2. 账号疑似被盗怎么办？
3. 密码应该怎么设置更安全？
4. 文件能不能上传到外部网盘？
5. 连接公共 WiFi 是否安全？

### 3.2 老师 / 部门管理员

这类用户更常涉及数据安全、权限申请、学生信息处理和外部协作等场景。他们需要知道某些操作是否存在合规风险，以及具体应该走什么流程。

典型问题：

1. 收集学生信息需要注意什么？
2. 班级名单能不能发到微信群？
3. 科研数据能不能上传到第三方平台？
4. 外部人员访问系统如何申请权限？
5. 数据文件外发前是否需要审批？

### 3.3 信息中心 / 安全管理员

这类用户关注的是重复咨询减少、高频问题归类、Bad Case 沉淀和知识库持续优化。他们希望通过 AI 助手降低重复答疑成本，同时发现用户最常遇到的安全问题。

典型问题：

1. 用户最常问哪些安全问题？
2. 哪些问题需要转人工处理？
3. AI 哪些回答容易出错？
4. 知识库还缺哪些内容？
5. 哪些问题属于高风险咨询？

## 5. 用户问题与痛点分析

### 场景 1：钓鱼邮件处理

普通用户在收到陌生发件人邮件、异常链接或要求输入账号密码的邮件时，往往难以判断邮件是否可信。由于缺乏安全知识，用户可能直接点击链接或下载附件，从而造成账号泄露风险。因此，该场景需要 AI 助手提供钓鱼邮件识别方法、风险等级提示和上报建议。

### 场景 2：账号异常处理

当用户发现账号异地登录、密码异常或无法正常登录时，通常不知道问题是否已经构成安全事件，也不清楚应先修改密码、检查登录记录还是联系管理员。该场景需要 AI 助手提供明确的处理步骤，并在高风险情况下提示尽快转人工处理。

### 场景 3：数据安全咨询

老师、部门管理员或普通员工在处理学生信息、科研数据、业务文件时，可能不确定是否可以通过微信群、外部网盘或第三方平台传输文件。该场景需要 AI 助手根据数据安全规范提供合规提示和处理建议。

### 场景 4：权限申请咨询

用户在申请系统权限时，往往不清楚申请入口、审批流程、权限范围和有效期限要求。该场景需要 AI 助手基于权限申请流程文档，提供简明的流程说明和最小权限原则提示。

### 场景 5：高风险问题边界

当用户提出涉及攻击、绕过、破解、入侵或恶意利用的问题时，系统不能提供具体操作方法。该场景需要 AI 助手识别高风险意图，拒绝输出危险内容，并引导用户通过正式授权流程或联系安全管理员。

## 6. 当前解决方式与不足

| 当前方式 | 优点 | 不足 |
| --- | --- | --- |
| 查制度文件 | 内容权威 | 文档分散、表达正式、查询效率低 |
| 问管理员 | 答案较准确 | 人工成本高、响应时间不稳定 |
| 问同学或同事 | 沟通方便 | 答案可能不准确，缺少依据 |
| 自己搜索 | 获取信息快 | 不一定适用于本校或本企业制度 |
| 通用大模型 | 交互自然 | 可能幻觉，缺少知识库依据和安全边界 |

## 7. 用户需求提炼

基于上述场景，用户的核心需求可以归纳为以下几类：

1. 快速问答需求：用户希望用自然语言提问，而不是自己查找多个制度文件。
2. 风险判断需求：用户希望知道当前问题属于低风险、中风险还是高风险。
3. 流程指导需求：用户希望获得清晰的下一步操作建议。
4. 引用依据需求：用户希望知道回答来自哪类制度、FAQ 或流程说明。
5. 高风险转人工需求：遇到疑似账号泄露、数据泄露或危险请求时，系统需要提示联系管理员。
6. 知识库优化需求：管理员希望通过用户反馈和 Bad Case 分析发现知识库缺口。

## 8. 场景优先级排序

| 优先级 | 场景 | 原因 |
| --- | --- | --- |
| P0 | 安全知识问答 | 最基础功能，支撑整个产品 |
| P0 | 钓鱼邮件处理 | 高频且风险明确，适合做示例 |
| P0 | 账号异常处理 | 风险较高，能体现风险等级 |
| P1 | 数据安全咨询 | 有合规价值，但知识库要求更高 |
| P1 | 权限申请流程 | 适合 RAG，但需要流程文档 |
| P2 | 管理员后台分析 | 有价值，但第一版可以简化 |
| P2 | 真实工单流转 | 工程复杂度较高，暂不做 |

## 9. 场景到功能的映射

| 用户场景 | 用户痛点 | 产品功能 |
| --- | --- | --- |
| 收到疑似钓鱼邮件 | 不知道是否能点击，也不知道如何处理 | 钓鱼邮件知识问答、风险等级、处理建议 |
| 账号疑似被盗 | 不知道问题严重程度和补救步骤 | 账号安全问答、高风险提示、联系管理员 |
| 文件外发或上传网盘 | 不确定是否涉及数据安全风险 | 数据安全问答、合规提示、引用来源 |
| 系统权限申请 | 不知道申请流程和权限范围 | 权限申请流程问答 |
| 高风险请求 | 可能诱导模型输出危险内容 | 拒答策略、转人工提示 |
| 管理员优化知识库 | 不知道哪些问题回答不好 | 用户反馈、Bad Case 记录 |

## 10. 后续验证方式

后续将通过 50 条测试问题验证核心场景覆盖情况。测试问题将覆盖账号安全、钓鱼邮件、数据安全、权限申请和高风险拒答等类型，并通过回答准确率、风险等级判断、拒答准确率和 Bad Case 类型分布判断当前场景设计是否合理。

如果测试集中某类问题 Bad Case 较多，说明该场景下知识库内容、Prompt 规则或风险判断逻辑仍需优化。
