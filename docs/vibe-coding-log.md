# AI-assisted Coding Log

## 1. 使用工具

- Dify
- Streamlit
- Python
- Cursor / ChatGPT
- GitHub

## 2. 本阶段开发目标

在 Dify 知识库问答应用基础上，使用 AI-assisted coding 完成 Streamlit 前端 Demo，并进一步接入 Dify API，使用户能够通过网页输入安全咨询问题、查看 AI 回答、提交反馈。

## 3. 开发流程

本项目采用以下流程完成原型开发：

1. 根据 PRD 拆解前端功能。
2. 使用 Streamlit 完成最小可运行页面。
3. 使用 mock 逻辑验证页面结构和用户交互。
4. 获取 Dify 应用 API Key。
5. 使用环境变量管理 API Key。
6. 封装 Dify API 调用模块。
7. 将 mock 回答升级为“优先调用 Dify API，失败时回退 mock”的结构。
8. 本地运行并测试问题输入、回答展示和反馈保存功能。

## 4. 示例任务 1：Streamlit 前端 Demo

需求：

用户可以在网页输入网络安全咨询问题，系统展示问题类型、风险等级、简要结论、原因说明、建议操作和是否需要联系管理员。

AI 辅助方式：

使用 Cursor / ChatGPT 根据功能需求生成初版 Streamlit 页面代码。

人工检查内容：

1. 页面结构是否符合 PRD。
2. 是否支持用户输入问题。
3. 是否能展示结构化回答。
4. 是否能保存“有帮助 / 没帮助”反馈。
5. 是否避免实现无关功能，例如登录系统、复杂数据库和后台权限。

## 5. 示例任务 2：Dify API 调用模块

需求：

通过 Python 调用 Dify Chat API，将用户问题发送给 Dify 知识库应用，并返回 AI 回答。

AI 辅助方式：

使用 Cursor / ChatGPT 辅助生成 `dify_client.py`，包括 API 请求、环境变量读取和异常处理。

人工检查内容：

1. API Key 是否通过 `.env` 读取，而不是写死在代码中。
2. 请求体是否包含 `inputs`、`query`、`response_mode`、`conversation_id` 和 `user`。
3. 是否使用 blocking 模式，降低初版接入复杂度。
4. 接口失败时是否有清晰错误提示。
5. 是否保留 mock 兜底，保证 Demo 可演示。

## 6. 示例任务 3：Dify 回答解析

需求：

将 Dify 返回的结构化文本解析为前端可展示的字段，包括问题类型、风险等级、简要结论、原因说明、建议操作和是否需要联系管理员。

AI 辅助方式：

使用 AI 工具辅助编写 `parse_dify_answer()` 函数，将固定字段解析为字典结构。

人工检查内容：

1. 是否能处理中文冒号和英文冒号。
2. 是否能在字段缺失时保留原始回答。
3. 是否能在解析失败时不影响页面运行。
4. 是否保留“查看 Dify 原始回答”的入口，便于后续 Bad Case 分析。

## 7. 当前实现说明

当前版本支持两种模式：

1. Dify API 模式：优先调用 Dify 知识库应用，展示真实 AI 回答。
2. Mock 兜底模式：当 API Key、网络、接口配置或 Dify 服务异常时，系统自动使用本地 mock 回答，保证 Demo 可运行。

该设计避免了接口问题导致项目无法演示，也体现了基础异常处理能力。

## 8. 反思

AI-assisted coding 提高了原型开发效率，但不能替代产品需求拆解、功能边界判断、代码审查和测试验证。本项目中，AI 工具主要用于辅助生成前端代码、API 调用模块和解析逻辑；本人负责确定产品功能、设计字段结构、检查安全边界、运行测试并修正问题。
