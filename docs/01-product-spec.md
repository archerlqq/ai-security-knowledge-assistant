## 1. 一句话定位

面向高校师生与企业员工，在账号异常、钓鱼邮件、数据外发、权限申请等场景中，提供**边界清晰、可追溯到制度依据、带风险等级与处理建议**的安全问答服务。

它不是通用聊天机器人，也不是攻防工具。

## 2. 背景与问题

安全制度、FAQ、审批流程通常分散在多个文档和通知里，表达正式、检索成本高。普通用户遇到问题时有两个典型困境：**不知道该问谁**，以及**不知道该多着急**（无法判断是普通咨询还是已经出事）。对信息中心而言，大量重复咨询占用了本可用于处置真实事件的时间。

## 3. 目标用户

| 角色 | 典型诉求 | 对产品的期待 |
| --- | --- | --- |
| 普通学生 / 员工 | 收到的邮件能不能点、账号是不是被盗、文件能不能外发 | 快、说人话、给下一步动作 |
| 老师 / 部门管理员 | 学生信息怎么处理、权限怎么申请、数据外发是否合规 | 有制度依据、能交代得清 |
| 信息中心 / 安全管理员 | 哪些问题最常被问、哪些答错了、知识库缺什么 | 可统计、可维护、可追责 |

## 4. 核心场景

| 编号 | 场景 | 用户问题示例 | 产品响应 |
| --- | --- | --- | --- |
| S001 | 钓鱼邮件 | 收到可疑邮件，不知道能不能点 | 识别要点 + 风险等级 + 上报路径 |
| S002 | 账号异常 | 账号疑似被盗或异地登录 | 改密、查登录记录、联系管理员 |
| S003 | 数据安全 | 文件能不能传外部网盘 | 合规判断 + 传输注意事项 |
| S004 | 权限申请 | 不知道怎么申请系统权限 | 申请要素 + 最小权限原则 |
| S005 | 高风险边界 | 询问绕过、破解、入侵方法 | 拒答 + 授权流程引导 |
| S006 | 知识库维护 | 管理员想知道哪些问题答不好 | 反馈与 Bad Case 沉淀 |

优先级：S001/S002 为 P0（高频且风险明确），S003/S004 为 P1（需更完整的制度语料），S005 为 P0（安全底线），S006 为 P2（第一版可简化）。

## 5. 用户痛点

1. **制度分散**：同一件事的信息散落在通知、附件、FAQ 里，找不到就对不上。
2. **无法判断严重程度**：把"应该立刻改密"当成"回头再说"，或把普通咨询当成事故。
3. **不知道找谁**：不清楚该找信息中心、教务还是本部门管理员。
4. **重复答疑成本高**：密码规范、钓鱼识别这类问题每天被问很多遍。
5. **缺少边界控制**：通用模型会直接回答不该公开的操作性问题。

## 7. 用户流程

提问 → 识别类型 → 判断是否高风险 → （是）拒答并引导授权/转人工 → （否）检索知识库 → 生成结构化回答 → 展示类型/风险/结论/原因/建议/是否找管理员 → 用户反馈 → 记录。

## 8. 验收口径

| 功能 | 验收标准 | 当前实测 |
| --- | --- | --- |
| F001 | 常见问题能给出结构完整、有依据的回答 | 常规集 100%，口语改写 22.5%（见 03 文档） |
| F002 | 类别归入合理范围 | 常规 100%，变体 45% |
| F003 | 风险等级与标注一致 | 常规 100%，变体 40% |
| F004 | 至少一条明确下一步动作 | 模板保证，覆盖率 100% |
| F005 | 应拒答的问题不输出具体方法 | 常规 100%，注入集 30% |
| F006 | 能沉淀问题、回答、反馈 | 已实现，样本仅 3 条 |
| F008 | 能看高频问题与缺口 | 未实现 |

## 9. 非目标

1. 不做真实工单系统与流转。
2. 不做复杂权限体系。
3. 不接入真实敏感数据。
4. 不提供攻击、绕过、入侵、破解的操作方法。
5. 不做企业级部署与高可用。

## 10. 指标定义（产品侧）

| 指标 | 定义 | 当前是否可算 |
| --- | --- | --- |
| 自助解决率 | 未转人工且反馈有帮助的会话占比 | ❌ 缺会话与转人工数据 |
| 高风险召回率 | 应转人工的高风险问题被正确识别的比例 | ✅ 评测侧可算 |
| 有帮助率 | 反馈"有帮助" / 总反馈 | ⚠️ n=3，无意义 |
| 首响时延 | 从提交到出结果 | ❌ 未埋点 |
| 知识缺口数 | 知识库外问题去重后的条数 | ✅ 评测侧可算（20 条） |

> 指标口径的完整定义见 `03-eval-spec.md` 第 4 节。

## 11. 差异化

1. **风险分级**而不只是知识问答：回答里带"这件事有多急"。
2. **拒答边界**：把"防御性提问"与"攻击性请求"分开，避免误伤。
3. **可评测**：有分层测试集与定量结论，而不是"感觉还行"。

## 12. 迭代路线

已做：分层评测体系（03 文档）。
下一步：Dify 全量回归 → 知识缺口清单 → 管理员看板（F008）→ 会话埋点。

## 13. 异常与边界处理

| 异常情况 | 期望行为 | 当前实现 |
| --- | --- | --- |
| 知识库无相关内容 | 明确说"无法确认"，建议联系信息中心 | ❌ 规则引擎全编答案（承认未知率 0%） |
| 问题过于模糊 | 引导补充场景 | ✅ 兜底话术已覆盖 |
| 用户提出高风险请求 | 拒答 + 授权路径 | ⚠️ 字面危险词可拒，纯指令型注入失效 |
| 模型输出格式不完整 | 记录 Bad Case，调 Prompt | ✅ 有解析兜底与原始回答留存 |
| 风险等级判断错误 | 归因到规则缺判据，补分类依据 | ✅ 评测侧可统计 |
| 引用来源错误 | 优化分段与检索配置 | ⚠️ 未评估检索层 |
| 接口超时/无 key | 回退本地引擎，保证 Demo 可用 | ✅ 双通道兜底；评测时此类样本剔除出分母 |
